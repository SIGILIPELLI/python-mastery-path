Quality & verification

How Mastery Path defines, counts and checks its courses. These rules decide every number on the site and in the record evidence. Methodology version 1.0 (2026-11-23).

1. Educational quality policy

Every course is written to teach a subject end to end in four progressive levels, with runnable or practical examples in each lesson, exercises, module quizzes, level projects and a final capstone. Courses are free to read with no account. Content is published from public source repositories, so every change is dated and traceable.

2. Definitions used for counting

CourseA self-contained, first-party learning programme published at learnmasterypath.com/<course>/ with its own syllabus, four progressive levels and lessons. One course is counted once, however many learning paths include it.
Learning levelOne of four ordered stages of a course (Level 1 Entry/Foundation, Level 2 Intermediate, Level 3 Advanced, Level 4 Master), each with its own overview page.
ModuleOne topic unit within a level. On Mastery Path each module is published as exactly one lesson page, so module and lesson counts are the same; module IDs record the level and position.
LessonA published page under level-N/ that teaches one topic and is not a project or capstone. It counts as a qualifying lesson when it returns HTTP 200 and has at least the minimum number of words of published text. The minimum is 300 words.
ExerciseA practice task inside a lesson, identified by a section heading that starts with Exercise/Exercises/Practice/Try it. Counted per section; not counted as lessons.
QuizA module quiz (per lesson, from the hub's question bank) or a course's final quiz page. Not counted as lessons.
ProjectA build task published as its own page (slug contains 'project' or 'capstone'). Counted separately; never included in lesson counts.
CapstoneThe final project page of Level 4 (one per course at most). Counted separately from other projects and from lessons.

3. Course eligibility criteria

A course qualifies for platform and record measurements only when all of these automated checks pass and a human content review is recorded:

  1. Accessible: the course home page returns HTTP 200 without login.
  2. Published: listed in the site's sitemap and not marked noindex.
  3. Four levels: each of Levels 1–4 has at least 5 lessons.
  4. Syllabus: the course home links to its levels.
  5. Substantive: at least 20 lessons, with no more than 2 under 300 words.
  6. Lessons reachable: every lesson URL returns HTTP 200.
  7. Practical: at least one project.
  8. Not a duplicate: no exact or near-duplicate lesson text shared with another course (see 6).
  9. First-party and free: hosted on learnmasterypath.com from the owner's repositories; no payment or registration.
  10. Human review: a named reviewer has read the course and recorded a dated review. Until then the status is "eligible – human review pending".

4. Course classification

Technology: the course teaches a programming language, software tool, platform, engineering or computing discipline. Professional development: the course teaches management, leadership, language, accounting/tax or marketing practice, even where software is used. Borderline cases are recorded with a note in the registry (for example Tally Prime & GST: accounting practice taught in software, classified professional). Both groups stay on the platform; the classification only decides which measurements a course belongs to.

5. What is never counted

  • Projects, capstones, exercises and quizzes are never counted as lessons.
  • A course used in several learning paths is counted once (one course ID).
  • Level overview pages, interview-question pages, cheat sheets, privacy and licence pages are not lessons.
  • External links (official documentation, videos on other sites) are references, never courses.
  • Learner, visitor or completion numbers are not published because they are not measured as verifiable counts.

6. Duplicate detection

Each audit checks exact duplicate course IDs, slugs and normalised URLs; fingerprints the text of every lesson (SHA-256 of normalised text) to find identical lessons across courses; compares 5-word shingles of lessons with the same title (Jaccard ≥ 0.6) to find near-duplicates; and flags course titles that are very similar (ratio ≥ 0.86). Similarity only flags candidates for human review; nothing is removed automatically. Latest audit: 1 candidate(s) – see duplicate candidates (CSV).

7. Accessibility policy

Pages target WCAG 2.2 AA: semantic headings, keyboard-reachable controls with visible focus, sufficient colour contrast in light and dark mode, labelled form fields, text that reflows on phones, and reduced motion when the device asks for it. Problems can be reported through the contact page.

8. Content review and publication

Courses are written in Markdown in public GitHub repositories and published automatically when changes are merged, so each lesson's history is public. A content review is recorded in registry/reviews.json with the course ID, reviewer, date and notes; the most recent review becomes the course's "last reviewed" date. Corrections from learners are welcome and are fixed in the source.

9. Verification and audit process

The audit tool (tools/registry/build_registry.py) reads the live published site, so it measures what learners can actually open: every course's published pages, every lesson's text, quiz banks and sitemaps. It then requests every lesson URL, applies the rules above, and writes dated evidence files with SHA-256 checksums. Audit IDs and timestamps are never edited afterwards; each archived audit lives in its own folder under registry/audits/.
