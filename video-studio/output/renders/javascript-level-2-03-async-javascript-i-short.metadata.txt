Title: Why a Promise always beats setTimeout(0) in JavaScript

Description:
A zero millisecond setTimeout still runs after every line of synchronous code, and a Promise callback jumps ahead of it every time. This Short walks through the event loop's three lanes: sync code on the call stack, then the microtask queue, then the task queue. Once you can see those lanes, async JavaScript stops feeling like magic.
